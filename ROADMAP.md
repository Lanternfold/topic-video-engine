# Project Roadmap

This roadmap is the shared progress ledger for the Topic Video Engine. Statuses reflect evidence currently recorded in the repository, not optimism.

## Current snapshot

- **Project shape:** local-first vertical-video renderer with sample creative profiles.
- **First pilot:** Paranormal Case File, about Skinwalker Ranch.
- **Current production maturity:** early prototype. Rendering and pre-flight review exist; the end-to-end approved, evidence-backed, motion-rich production workflow is not yet proven.
- **Tests:** run locally after installing `requirements.txt`; do not mark green without recording the actual result.
- **Publishing:** manual. Do not automate publishing before the first Reel is published and reviewed.

## Milestones

| ID | Milestone | Status | Exit criteria |
|---|---|---|---|
| M0 | Define creative and quality gates | In progress | Creative brief required for final output; evidence statuses required; tests pass; audit checks are trustworthy |
| M1 | Produce and publish first Reel | Planned | Skinwalker Ranch pilot reviewed, rendered, checked on a phone, and manually published |
| M2 | Make production repeatable | Planned | Documented idea-to-export workflow; timeline/audio/captions and real motion represented and validated |
| M3 | Add assisted automation | Later | Automation prepares work but pauses for human approval before creative production |
| M4 | Learn from performance | Later | Record post-level metrics and use them to inform future experiments without treating correlation as proof |

## Immediate next actions

1. Install dependencies in a virtual environment and run the test suite; record the result.
2. Close approval and evidence-validation gaps, keeping preview exceptions explicit.
3. Strengthen audit behavior and apply safe-area rules consistently.
4. Define a timeline model for scene timing, transitions, narration, captions, and audio.
5. Build and review the Skinwalker Ranch pilot using the Paranormal Case File treatment.
6. Benchmark local production time and render performance before choosing paid infrastructure.

## Working rules

- Human approval is required before a creative brief enters production.
- Every factual claim needs a traceable source and an explicit verification status.
- A broad source does not automatically substantiate a precise statistic or benchmark.
- Prefer small, reviewable changes over broad rewrites.
- Keep infrastructure local and low-cost until measured needs justify a change.
- Update this file when a milestone changes, and link evidence such as test output, a rendered preview, or a published Reel.
